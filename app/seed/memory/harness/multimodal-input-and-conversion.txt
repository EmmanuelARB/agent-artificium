Purpose

Handle non-text evidence without confusing a durable attachment path with model
perception. Artificium's built-in provider transport supports images only.
Everything else can remain durable while an appropriate tool converts or
analyzes it.

Images

- An image attachment is inert until `load_images` selects it. Load one image or
  several related images in one call when comparison matters.
- Prefer `retention:"once"`: the selected images enter the next successful
  inference and are then automatically released. Provider failure does not
  consume them.
- Use persistent retention only for genuinely multi-step visual reasoning.
  Persistent images are input again on every inference, so inspect
  `list_loaded_images` and call `release_images` as soon as repeated perception
  no longer helps. Working-memory offloading also releases all active images.
- Loading the same path again refreshes its settings rather than duplicating it.
  Releasing visual context never deletes the durable source file.
- When configured vision is `no`, or `auto` falls back after provider rejection,
  use a local vision/OCR tool instead of pretending the image was seen.

Conversion strategies

- Speech/audio: preserve the original; transcribe with timestamps and, when
  relevant, speaker separation. Retain uncertainty for names, numbers, and
  low-confidence segments. A transcript is evidence derived from audio, not the
  audio itself.
- Video: inspect metadata and audio; use scene detection or sampled keyframes,
  then load selected frames as images. Preserve source timestamps so a claim can
  be traced back and finer frames can be extracted around an event.
- PDF/document: extract embedded text first; render and OCR only pages that need
  visual/layout inspection or have no reliable text layer. Use Infinite
  Attention over large extracted text or page manifests.
- Unknown binary: identify MIME type and container without executing untrusted
  content; select a bounded parser or converter and retain its version, command,
  output path, and limitations.

Tool and memory placement

Reusable converters, transcribers, capture clients, and OCR apparatus belong
below `mind/tools/`; their operating knowledge belongs below `memory/tools/`
and important verified apparatus should be registered in meta-memory. Temporary
frames, transcripts, and project assets belong in a descriptive project below
`mind/space/` or logs, not in semantic memory. Save only reusable lessons,
provenance, constraints, and retrieval routes as memory.

Verification

Conversion is lossy. Compare a sample against the source, preserve time/page/
frame references, and distinguish what was directly perceived from what a tool
inferred. If exact wording, small text, or subtle visual structure matters,
reprocess the suspicious range at higher fidelity rather than generalizing from
a coarse conversion.
